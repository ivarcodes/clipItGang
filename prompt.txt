Shorts-maker run requirements (from user)
=========================================
Video: reference/AMA [s-OS25VjRSs].mkv (2h 21m, 1920x1080 60fps, Opus stereo).

Goal
----
ONE flagship, story-driven vertical video, under 1:30 (target ~89s):
1. Intro: the user introduces the Charizard box and the cards.
2. Unboxing: all five packs, in order, with the best pulls.
3. Payoff: the last-pack hit, the value reaction, and the two favourite cards.

Not ten separate shorts. Pick the best moments, cut dead air, and merge them
into one narrative. Keep the spoken words verbatim in captions (including
mispronunciations and slang); never "fix" names.

Project layout
--------------
reference/       the source video (ignored by git)
clips/           rendered video (ignored by git)
shorts-maker/    tooling, docs, fonts
.venv/           Python environment
prompt.txt       this brief
transcriptions/  temporary word-level transcript (removed by final cleanup)
clips.json       temporary render spec (removed by final cleanup)

Hard requirements
-----------------
1. Do NOT use 100% of the laptop's resources. The user may be streaming. Keep
   CPU load low, run jobs sequentially, no parallel renders, no GPU assumptions.
2. The final story video must be UNDER 1:30. Keep the full 14-beat storyboard
   you liked: a 3s cold-open hook + box/card intro + all five packs + payoff.
   After removing only real dead air it is ~74s; pass --max-duration 89.
3. Extract the entire transcript first, read it, then pick the story beats from
   the whole unboxing, not from random samples.
4. Full-screen 9:16 crop, no blurred bars. Set crop_x per segment to keep the
   hands/cards in frame.
5. Captions must be perfectly aligned, legible and verbatim. Use the phrase-aware
   Archivo Black style (112 px, 9 px outline, 5 px shadow, 3 px spacing, bottom
   baseline y=1620, white inactive words, warm yellow active word, pop-in/fade).
6. The speaker must be speaking through the WHOLE video: remove only genuine
   dead air (gaps >= 0.5s) with strip_silence.py. Do NOT chop short fragments
   or drop whole beats -- keep every visual moment from the original cut.
7. Transitions: subtle J-cuts and L-cuts (--jl-lead 0.12), not dissolves.
   Alternate jcut/lcut at beat changes; internal trims are hard cuts.
8. Only use the user's own content / content they have permission to reuse.
9. Must work with any LLM / any API provider. No vendor lock-in, no API keys.

OBS rule (IMPORTANT)
--------------------
- NEVER close, stop, restart, kill or signal OBS. Detect it read-only via /proc.
- The scripts auto-detect OBS; no manual checking needed.
- OBS running  -> 2 cores, nice 19, ionice idle (stream gets priority).
- OBS off      -> up to 6 cores, nice 19, ionice best-effort.
- Never use 100% of the machine.
- Transcribe in 10-minute chunks with MemoryMax=2.2G. Never run a full-file
  model without a memory cap.

Rendering defaults for this run
-------------------------------
- FFmpeg: --threads auto (OBS-aware), one render at a time, `--lowmem` (one
  short-lived process per segment) so OBS/VS Code are never OOM-killed.
- Reframe: crop, 1080x1920, 60fps at crf 16, AAC 192k (YouTube upload quality).
- Captions: Archivo Black, 3 words / 16 chars per card, phrase breaks,
  2-line balanced wraps, exact transcript text.
- Silence: re-read the full transcript, then run
  strip_silence.py clips.json --transcript ... --out clips_silent.json
  --min-gap 0.5 --min-part 0.6. Removes ~17s of dead air, keeps 28 parts.
- Transitions: subtle J-cut / L-cut, --jl-lead 0.12, alternating at beat
  boundaries; no dissolves. Audio is a seamless concat.
- Final command: render_clips.py clips_silent.json --transcript ... --out clips
  --reframe crop --caption-style bold --max-words 3 --max-duration 89
  --jl-lead 0.12 --lowmem --fps 60 --preset fast --crf 16 --threads auto
- Verify duration, resolution, fps, audio, silencedetect, crops and caption sync
  across all beats before reporting.

temp artifacts.
